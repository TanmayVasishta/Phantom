# Project HELIX: Hybrid Environment for Localized Intelligence and eXecution
## Comprehensive "Pin-to-Pin" Description

Project HELIX is a privacy-first AI Operating System middleware. It is designed to act as an intelligent intermediary between a user and their machine, capable of executing local OS commands deterministically and delegating complex reasoning or research tasks to cloud-based LLMs—all while ensuring user privacy by redacting Personally Identifiable Information (PII) before any data leaves the local machine.

### Core Philosophy
- **Privacy-First**: No PII leaves the local machine. All user requests are first parsed by a local, offline model.
- **Speed & Determinism**: Simple OS tasks (opening apps, moving files) are handled instantly via Regex fast-paths (0ms delay), bypassing expensive LLM inference completely.
- **Hybrid Architecture**: Leverages local small models for fast intent classification and PII redaction, while utilizing powerful cloud models for general knowledge and reasoning tasks.
- **Multi-Step Automation**: Capable of chaining tasks, such as conducting cloud-based research and saving the results locally, or drafting emails securely.

## 1. Architectural Components

### 1.1 Router (`core/router/router.py`)
The central orchestrator of HELIX. Every user prompt goes through the Router, which executes a defined pipeline:
- **Step 0 & 0.5 (Fast-Paths)**: Checks for system commands (`audit log`, `stats`) and multi-step chains (`research X and save`).
- **Step 1 (Regex Fast-Path)**: Immediately executes obvious OS commands (e.g., `open chrome`, `list downloads`) by routing them directly to the `FileManager`.
- **Step 2 (Memory)**: Retrieves relevant context from the local ChromaDB vector store.
- **Step 3 (Sentinel Classification)**: Sends the prompt to the local `SentinelNode` to classify intent (`local` vs. `cloud`) and strip PII.
- **Step 4 (Routing & Execution)**:
  - If `local`: Checks for destructive commands (prompts user for confirmation). Attempts execution via `FileManager`. If `FileManager` can't handle it deterministically, escalates to `CloudCommandParser` to parse the intent into a structured JSON command for local execution.
  - If `cloud`: Forwards the *sanitized* prompt to the `CloudOracle` for reasoning/knowledge generation.
- **Step 5 (Store & Audit)**: Saves the interaction to Memory and logs the event in the Audit system.

### 1.2 Sentinel Node (`core/sentinel/node.py`)
The local, offline gatekeeper running via Ollama (currently configured for a small, fast model like `qwen3.5:2b`).
- **Function**: Performs a single LLM call with a few-shot prompt to simultaneously:
  1. Classify the intent as `local` (OS operations) or `cloud` (knowledge/reasoning).
  2. Redact PII (Names, Paths, Emails, Phone numbers) into placeholders (e.g., `[NAME]`, `[PATH]`).
- Ensures high privacy and security before any data is sent to external providers.

### 1.3 Cloud Oracle (`core/oracle/cloud.py`)
A robust, multi-provider cloud interface.
- **Providers**: Supports Groq, DeepSeek, OpenRouter, and Google Gemini via API keys configured in `config/settings.py`.
- **Fallback Mechanism**: Attempts providers in sequence. If one fails (due to quota limits, downtime, etc.), it seamlessly falls back to the next available provider.
- **Role**: Handles complex, non-OS tasks such as answering general knowledge questions, writing code, or summarizing text. It only ever receives PII-sanitized prompts from the Sentinel Node.

### 1.4 File Manager & Middleware (`core/middleware/file_manager.py`)
The execution engine for local OS commands.
- **Regex Fast-Paths**: Contains a list of compiled regex patterns to instantly identify actions like moving, copying, deleting, organizing files, or launching apps.
- **App Registry**: Maps natural language aliases (e.g., "vs code", "browser") to system executables.
- **Destructive Gates**: Identifies potentially harmful commands (delete, wipe, overwrite) and requires user confirmation before execution.
- **System Health**: Interfaces with `psutil` to generate comprehensive CPU, RAM, and disk usage reports.
- **Watchdog**: Runs background threads to proactively monitor specific folders (e.g., Downloads, Desktop) for new file creations or movements, pushing notifications to the user interface.

### 1.5 Multi-Step Chain Runner (`core/chains/multi_step.py`)
Enables complex automation sequences without relying on heavy LangChain dependencies.
- **Detection**: Uses regex to identify triggers like "research X and save to Y" or "draft an email about X".
- **Chains**:
  - **Research + Save**: Redacts PII from the topic -> Asks Cloud Oracle for research -> Saves the output as a `.txt` file locally using the `FileManager`.
  - **Draft Email**: Uses `EmailDrafter` to generate a privacy-safe email draft via the Cloud Oracle and, upon user approval, opens the default mail client (or Gmail) with the draft pre-filled.

### 1.6 Workflow Profiles (`core/profiles/profiles.py`)
Predefined, instant-execution environments.
- Users can trigger profiles like "code mode", "study mode", "presentation mode", or "focus mode".
- These profiles trigger a sequence of `FileManager` actions simultaneously (e.g., "code mode" opens VS Code, Spotify, and GitHub in Chrome instantly).

### 1.7 Memory & Audit Logging (`core/memory/memory.py` & `core/logging/audit_log.py`)
- **Memory**: Uses a local ChromaDB instance to store user interactions, creating a persistent vector space of past conversations. This provides context to future requests.
- **Audit Log**: Every routing decision, classification result, tool execution duration, and potential error is logged cleanly. Users can type `audit log` or `audit stats` to view system activity.

## Summary of Data Flow
1. User provides input (text or voice-to-text).
2. `Router` checks for 0ms regex fast-paths or multi-step chains. If matched, it executes locally instantly.
3. If no fast match, prompt goes to `SentinelNode`.
4. `SentinelNode` classifies intent (`local` or `cloud`) and creates a `sanitized_prompt` (PII removed).
5. Router directs the request:
   - **Local Intent**: Directed to `FileManager`. If ambiguous, `CloudCommandParser` parses the intent into a JSON OS command, which is then executed locally.
   - **Cloud Intent**: Forwarded to `CloudOracle` which queries Gemini/Groq/etc. using the *sanitized* prompt.
6. The response is presented to the user, the context is saved to local `Memory`, and the exact trace is logged in `Audit`.
